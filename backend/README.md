# Coolay backend

Zero-dependency Node.js бэкенд (`node:http`) — прокси к kie.ai для AI-студий Coolay.
Секреты в код не попадают: ключ читается из `.env` рядом с бэкендом.

## Запуск

```bash
cp .env.example .env      # и подставить KIE_API_KEY
node server.js            # PORT=8821 по умолчанию
```

Без `KIE_API_KEY` процесс падает сразу с понятной ошибкой (fail-fast), а не
получает 401 от kie.ai в рантайме.

## Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| GET  | `/api/health`      | Проверка живости; `sku:true` подтверждает, что SKU-роуты подключены |
| POST | `/api/generate`      | Генерация изображения (старый инструментальный поток) |
| POST | `/api/generate-smart`| Генерация с авто-подбором промпта |
| POST | `/api/sku/analyze`   | Gemini 3.6 Flash: распознавание товара по фото |
| POST | `/api/sku/content`   | Контент карточки RU/EN/UZ/TR + характеристики + SEO, выдаёт SKU |
| POST | `/api/sku/images`    | Nano Banana 2 Lite: постановка задач на студийные фото |
| GET  | `/api/sku/task`      | Батч-опрос статусов задач: `?taskIds=a,b,c` |
| GET  | `/api/sku/slots`     | Каталог слотов изображений |

## Особенности интеграции с kie.ai

Найдено опытным путём, ломать не стоит:

- **Изображения в Gemini передаются только как `inline_data: {mime_type, data}`.**
  Вариант с `image_url` возвращает HTTP 500.
- **Схемы `functionDeclarations` должны быть плоскими.** `gemini-3-6-flash` не
  переваривает вложенные `OBJECT` — в массивах приходят `null`. Поэтому
  характеристики передаются параллельными массивами `specLabels` / `specValues`,
  а контент генерируется отдельным вызовом на каждый язык.
- Слоты `main` / `cutout` / `folded` явно требуют «только товар»: если исходное
  фото снято на модели, модель протекает в результат.

## Деплой

`scripts/deploy.sh` во фронтенд-репозитории копирует `server.js`, `sku.js`,
`env.js` в прод и перезапускает `pm2 coolay-backend`, затем проверяет
`/api/health` на `"sku":true`. Файл `.env` на прод не копируется — он создаётся
на сервере один раз.
